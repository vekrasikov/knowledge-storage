# Ворота завершения изменения

Скилл дублирует то, что делают hooks, — и это намеренно. Hooks дают гарантию,
скилл даёт структуру отчёта. Если hooks у вас настроены, шаги 1–2 будут уже пройдены,
и вы просто подтверждаете результат.

## 1. Компиляция

```bash
./gradlew --offline compileJava compileTestJava
```

Не идти дальше, пока не зелено.

## 2. Инспекции IDE

Вызови `mcp__ide__getDiagnostics` по каждому изменённому файлу.

`javac` пропускает то, что IDEA видит: nullability, неиспользуемые элементы, неверное
применение Spring-аннотаций, битые плейсхолдеры в `@Value`, ошибки в JPQL внутри `@Query`,
несоответствие имён полей в derived query методах репозитория.

Если инструмент недоступен — скажи об этом явно и не выдавай отсутствие диагностики
за её отсутствие.

## 3. Миграции — самая частая пропущенная вещь

Ответь письменно на три вопроса:

1. Менялась ли структура `@Entity` (поля, типы, связи, ограничения, индексы)?
2. Если да — есть ли в изменении новый файл `db/migration/V{n}__*.sql`?
3. Точно ли не редактировалась уже применённая миграция?

Изменение сущности без миграции — незавершённая работа, даже если всё компилируется
и тесты зелёные (`ddl-auto: validate` уронит приложение на старте).

## 4. Тесты

- Затронутые тесты — обязательно, поимённо.
- Новый эндпоинт → `@WebMvcTest`. Новый запрос в репозитории → `@DataJpaTest`.
  Новая бизнес-логика → обычный unit-тест без контекста Spring.
- Не поднимай `@SpringBootTest` там, где хватает среза.
- Тест, который падал до твоих изменений, — отдельно назови в отчёте, не прячь.

## 5. N+1 и транзакции

Если добавлялась выборка со связями:

- проверь, что коллекции не грузятся лениво в цикле;
- используй `@EntityGraph` или `join fetch`;
- убедись, что читающие методы помечены `@Transactional(readOnly = true)`;
- внутри транзакции нет вызовов внешних сервисов.

## 6. Формат и архитектура

```bash
./gradlew --offline spotlessApply
./gradlew --offline test --tests 'ArchitectureTest'
```

## 7. Отчёт

Ровно в такой форме:

```
Сделано:
  - <файл>: <что и зачем>

Проверено:
  - компиляция: ok
  - инспекции IDE: ok / недоступны / N замечаний
  - миграция: добавлена V12__add_user_status.sql / не требуется, потому что <причина>
  - тесты: UserServiceTest ok, UserControllerTest ok
  - ArchUnit: ok

Не сделано / риски:
  - <что осталось и почему>
```

Не сообщай об успехе, если хоть один пункт не пройден. Честное «тест падает, вот вывод»
полезнее, чем зелёный отчёт, который не соответствует состоянию репозитория.
